# Learnings from ByteDance's Official Seedance 2.5 Prompt Writing Guide

Source: "Dreamina Seedance 2.5 Prompt Writing Guide," ByteDance's own official documentation, mirrored publicly at [docs.byteplus.com/en/docs/ModelArk/2607689](https://docs.byteplus.com/en/docs/ModelArk/2607689) (last updated August 31, 2026). This is a primary source directly from the vendor whose model this product's video generation is built on - materially more authoritative than the third-party research in `docs/director-mode-cinematography-research.md` and `docs/seedance-direct-api-research/`.

## What was implemented in `directorMode.ts` as a direct result

1. **Timestamp format now matches Seedance's own documented syntax exactly.** The guide's own examples use `"0-3 seconds...3-7 seconds"` and `"[1s-4s]....[4s-8s]"` - plain integer-second labels, not a clock format. `buildTimedStoryboard`'s `formatTimestamp()` used to produce an invented `"0:00-0:03"` style; since this string is sent directly to the model, matching its own documented convention is a real correctness fix, not cosmetic. Now produces `"0s-3s"`.
2. **Added a default "Do not add subtitles" constraint** to both `expandCinematicPrompt()` and `buildTimedStoryboard()`'s output. The guide explicitly calls this out under "Negative control" as a supported, commonly-needed constraint - unwanted spontaneous captions are a documented failure mode (also consistent with the earlier BytePlus 2.0 research's finding that portrait aspect ratio has a higher spontaneous-subtitle rate).
3. **Validated, not changed**: the existing "Build a cinematic scene" composite prompt (`generate-cinematic-scene/route.ts`) already opens with `"@Image1 is the character. @Image2 is the location."` - this matches the guide's own recommended asset-binding pattern almost exactly (`"Image 1 depicts the protagonist John and uses the voice timbre from Audio 1"`), and the existing camera-move library already pairs technical terms with plain-language explanations in the same string (e.g., dolly zoom's entry already reads "dolly zoom (vertigo effect), the camera dollies in while the lens zooms out... warping the background"), matching the guide's own recommendation for niche terms: "[term + descriptive explanation]." No changes needed to either.

## Real, concrete guidance confirmed (validates existing design choices)

- **The "one-sentence summary" formula the guide recommends** - `Subject + Location + Event + Genre/Style + Camera movement` - is essentially the same structure `expandCinematicPrompt`'s 6-block output already assembles.
- **"Give priority to general [action] descriptions... avoid repeating the same actions"** for performance direction - matches `buildTimedStoryboard`'s existing beat-cycling logic (camera moves and micro-performance details are cycled by index, never repeated back-to-back).
- **Reasonable duration allocation per timed segment**: "If too little plot is specified within a given time range, the model may improvise more freely. If too much content is packed in, the result may contain excessive cuts or omit parts of the plot." This directly validates using real shot-length (ASL) data to size beats (`PACE_PRESETS`, see `docs/shot-pacing-research.md`) rather than picking an arbitrary beat count.
- **"Not recommended to use timestamps to control high-frequency actions"** (e.g., "shake your head three times per second") - a real constraint worth remembering if this system is ever extended toward finer sub-second control.

## Real, concrete numbers worth knowing for future UI/reference-asset work (not yet acted on)

- Up to 50 total reference assets per request (30 images up to 4K, 10 videos totaling ≤30s, 10 audio clips totaling ≤30s).
- **1-5 subjects for audio/video references, 1-8 subjects for image references** generally produce the most stable results; beyond that, stability drops and multiple attempts may be needed. Worth surfacing as a soft warning in the "Cast & Locations" reference-picker UI if it's ever extended, rather than letting someone select 15 reference images with no signal that quality will likely degrade.
- **Multi-panel storyboards work best at 15 panels or fewer**, using simple stick-figure/line-art (not noisy AI-generated or heavily-texted storyboards) - the model treats these as a loose plot reference, not a strict frame-by-frame match.
- **Keyframe references** (as opposed to storyboard references) DO align strictly with the input images - a genuinely different, stricter input mode from storyboards.

## Real capabilities not yet built - flagged as strong next-step candidates, not built in this pass

1. **Native storyboard/keyframe image input.** Seedance 2.5 natively accepts a sequence of images as keyframes (with strict visual alignment) or a single multi-panel storyboard image (as a loose plot reference). This product's "Build a cinematic scene" feature currently produces one still composite image; extending it to generate a short sequence of simple keyframe images per beat (reusing `buildTimedStoryboard`'s beat structure) and passing them as native Seedance keyframe references would likely produce meaningfully more controlled results than text-only beat descriptions alone. This is a real, well-scoped next feature, not built here since it's a genuinely separate image-generation + API-wiring task.
2. **ByteDance's own official prompt-optimization skill.** The guide recommends installing it via `npx --yes skills@latest add "https://arkdocs-en.tos-ap-southeast-1.volces.com/skills/" --skill sd25-pe --yes`, then invoking it with `/sd25-pe <prompt>` in an AI chat context to have it refine a prompt before submission. This is a legitimate, vendor-provided tool that could be used as an external sanity-check against this project's own `expandCinematicPrompt()` output, or as a complementary manual tool for users. Not installed/run in this pass - flagged as something to try deliberately, with the user's awareness, rather than run unprompted as a side effect of reading the docs.
3. **Locked vs. unlocked task types and trigger keywords.** Editing, first/last-frame, and extension tasks each lock the output's aspect ratio (and sometimes duration) to match the input asset, and are triggered by specific keywords in the prompt (`edit video, add, insert, remove, delete, modify, replace, change to` for editing; `extend forward, extend backward, continue, continue from` for extension). Worth double-checking in the future that `expandCinematicPrompt`'s output never accidentally includes one of these trigger words when a plain reference-to-video generation (not an edit/extension) is intended - a quick audit confirmed none of the current genre/style library text does, but this is worth re-checking whenever new library content is added.
